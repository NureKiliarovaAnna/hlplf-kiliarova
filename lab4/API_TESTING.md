# Перевірка роботи API системи керування університетом

## Короткий опис

API працює з готовою SQL Server базою даних `UniversityManagementDb`.

Тестування виконується через Swagger:

```text
http://localhost:5150/swagger
```

SQL Server використовується локально через:

```text
.\SQLEXPRESS
```

Автентифікація до бази даних виконується через Windows Authentication. Логін і пароль не використовуються.

## Перевірка GET-запитів

### GET /api/Courses

Очікуваний результат: повертається список курсів. Для кожного курсу має бути `id`, назва, опис, кількість кредитів, `TeacherId` і повне ім'я викладача.

### GET /api/Students

Очікуваний результат: повертається список студентів. Для кожного студента має бути `id`, ім'я, прізвище, `email`, група, дата народження та дата створення запису.

### GET /api/Grades

Очікуваний результат: повертається список оцінок. Для кожної оцінки має бути `id`, `StudentId`, `CourseId`, значення оцінки, дата оцінювання, коментар, повне ім'я студента та назва курсу.

## Перевірка створення студента

### POST /api/Students

JSON:

```json
{
  "firstName": "Олег",
  "lastName": "Мельник",
  "email": "oleh.melnyk@nure.ua",
  "groupName": "ПЗПІ-23-3",
  "dateOfBirth": "2006-09-12"
}
```

Очікуваний результат: `201 Created`.

Після цього потрібно виконати `GET /api/Students` і переконатися, що новий студент з'явився у списку.

## Перевірка створення курсу

### POST /api/Courses

JSON:

```json
{
  "title": "Алгоритми та структури даних",
  "description": "Курс з базових алгоритмів, структур даних та оцінки складності.",
  "credits": 4,
  "teacherId": 1
}
```

Очікуваний результат: `201 Created`.

Після цього потрібно виконати `GET /api/Courses` і переконатися, що новий курс з'явився у списку.

## Перевірка створення оцінки

### POST /api/Grades

ВАЖЛИВО:

Для `studentId` і `courseId` потрібно використовувати реальні ідентифікатори, які існують у базі даних.

Якщо перед цим було створено нового студента й новий курс, їхні `id` можна взяти з відповідей `GET /api/Students` і `GET /api/Courses`.

JSON:

```json
{
  "studentId": 4,
  "courseId": 4,
  "gradeValue": 90,
  "gradeDate": "2026-05-27T09:49:54.419Z",
  "comment": "Гарне виконання практичного завдання"
}
```

Очікуваний результат: `201 Created`.

Після цього потрібно виконати `GET /api/Grades` і переконатися, що нова оцінка з'явилася у списку.

У відповіді мають відображатися `StudentId`, `CourseId`, `gradeValue`, `gradeDate`, `comment`, `studentFullName` і `courseTitle`.

## Перевірка оновлення оцінки

### PUT /api/Grades/{id}

ВАЖЛИВО:

Замість `{id}` потрібно вказати реальний `GradeId` оцінки, яку потрібно оновити.

JSON:

```json
{
  "studentId": 4,
  "courseId": 4,
  "gradeValue": 96,
  "gradeDate": "2026-05-27T09:49:54.419Z",
  "comment": "Оцінку підвищено після захисту роботи"
}
```

Очікуваний результат: `204 No Content`.

Після цього потрібно виконати `GET /api/Grades` і переконатися, що оцінку оновлено.

Ця операція виконується у транзакції:

- перевіряється існування студента
- перевіряється існування курсу
- оновлюється оцінка
- якщо всі дії успішні, виконується `Commit`
- якщо виникає помилка, виконується `Rollback`

## Перевірка видалення студента

### DELETE /api/Students/{id}

ВАЖЛИВО:

Замість `{id}` потрібно вказати реальний `StudentId`.

Бажано видаляти тестового студента, створеного під час перевірки, а не початкові записи.

Очікуваний результат: `204 No Content`.

Після цього потрібно виконати:

- `GET /api/Students`
- `GET /api/Grades`

Потрібно переконатися, що студент видалений, а його оцінки також більше не відображаються.

Видалення студента та його оцінок виконується у транзакції:

- спочатку видаляються оцінки студента
- потім видаляється студент
- якщо всі дії успішні, виконується `Commit`
- якщо виникає помилка, виконується `Rollback`

## Перевірка видалення курсу

### DELETE /api/Courses/{id}

ВАЖЛИВО:

Замість `{id}` потрібно вказати реальний `CourseId`.

Бажано видаляти тестовий курс, створений під час перевірки, а не початкові записи.

Очікуваний результат: `204 No Content`.

Після цього потрібно виконати:

- `GET /api/Courses`
- `GET /api/Grades`

Потрібно переконатися, що курс видалений, а пов'язані з ним оцінки також більше не відображаються.

Видалення курсу, занять та оцінок виконується у транзакції:

- спочатку видаляються оцінки курсу
- потім видаляються заняття курсу
- потім видаляється курс
- якщо всі дії успішні, виконується `Commit`
- якщо виникає помилка, виконується `Rollback`

## Перевірка кешування

- `GET /api/Courses` кешує список курсів з ключем `courses_list`
- `GET /api/Grades` кешує список оцінок з ключем `grades_list`
- час життя кешу становить 5 хвилин
- після `POST`, `PUT`, `DELETE` для `Courses` кеш `courses_list` очищується
- після `POST`, `PUT`, `DELETE` для `Grades` кеш `grades_list` очищується
- після `DELETE` для `Courses` також очищується `grades_list`, тому що видалення курсу може впливати на оцінки

## Перевірка обробки помилок

Приклади очікуваної поведінки:

- якщо `GET /api/Students/{id}` виконується з неіснуючим `id`, API повертає `404 Not Found`
- якщо `POST /api/Grades` має неіснуючий `studentId`, API повертає `400 Bad Request`
- якщо `POST /api/Grades` має неіснуючий `courseId`, API повертає `400 Bad Request`
- якщо `gradeValue` менше `0` або більше `100`, API має відхилити такі дані
- якщо `credits` менше `1` або більше `10`, API має відхилити такі дані

## Висновок

API реалізує керування студентами, курсами та оцінками, працює з SQL Server через Entity Framework Core, використовує кешування для часто запитуваних даних і транзакції для забезпечення цілісності даних.
